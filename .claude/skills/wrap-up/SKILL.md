# /wrap-up — 세션 마무리

다른 PC 에서 이 저장소를 pull 한 뒤에도 자연스럽게 이어서 작업할 수 있게, 이 세션의 기억을 저장소 안에 남긴다.
순서대로 전부 수행한다. 하나라도 건너뛰면 다음 세션이 그만큼 눈을 감고 시작한다.

## 1. 이 세션에서 한 일 되짚기

- `git status --short` 와 `git diff --stat` 으로 실제 변경 파일을 확인한다. 기억이 아니라 diff 를 근거로 쓴다.
- 이번 세션에서 내린 **결정**(왜 그렇게 했는지), 만난 **문제와 해결**, 아직 **안 끝난 것**을 뽑아낸다.

## 2. `docs/HISTORY.md` 갱신

### 2-a. 타임라인에 항목 1개 추가 (`## 타임라인` 바로 아래, 최신이 위)

```markdown
### YYYY-MM-DD · 세션 N · 한 줄 제목
- **한 것:** 변경 파일/기능을 구체적으로. 파일 경로 포함.
- **결정:** 무엇을 왜 그렇게 정했는지. 대안이 있었다면 왜 버렸는지.
- **문제/해결:** 막혔던 것과 해결 방법. 재발 방지 규칙이 생겼다면 CLAUDE.md 에도 반영.
- **검증:** 무엇을 어떻게 확인했는지 / 못 한 것은 못 했다고 명시.
- **다음:** 바로 이어서 할 일 한두 줄.
```

- 세션 번호는 직전 항목 + 1. 날짜는 오늘(시스템 날짜).
- 사소한 Q&A 만 있었던 세션은 항목을 만들지 않는다. 코드/문서/결정이 바뀐 세션만 기록한다.

### 2-b. 상단 3개 섹션은 **덮어쓰기**

- `## 현재 상태`: Phase, 빌드 상태(날짜 포함), 로컬에서 아직 안 한 것, 원격 저장소 상태.
- `## 다음 할 일`: 우선순위 순으로 다시 정렬. 끝난 항목은 지운다(타임라인에 남아 있다).
- `## 미결 결정`: 답이 나온 것은 지우고 타임라인 "결정" 으로 옮긴다. 새로 생긴 질문은 "기본 가정" 과 함께 추가.

## 3. CLAUDE.md 점검

이 세션에서 새로 알게 된 **규칙성 있는 사실**(예: 라이브러리의 함정, 빌드가 깨지는 패턴, 사용자가 명시한 선호)이 있으면 CLAUDE.md 의 해당 섹션에 한 줄로 추가한다. 일회성 사건은 HISTORY.md 에만 남긴다.

## 4. 검증

```bash
npx tsc --noEmit
npm run lint
npm run build
```

셋 중 실패가 있으면 고치거나, 고칠 수 없으면 HISTORY.md "현재 상태" 에 **빨간 글씨로** 실패 사실과 재현 방법을 적는다. 조용히 넘어가지 않는다.

## 5. 커밋

- `.env` 등 비밀이 스테이징되지 않았는지 `git status` 로 확인한다.
- 메시지는 한국어, 형식은 `타입: 요약` (타입: feat / fix / docs / chore / refactor). 본문에 HISTORY 항목 제목을 한 줄 넣는다.
- 원격(`origin`)이 있고 사용자가 push 를 원하면 push 한다. 원격이 없으면 사용자에게 `git remote add origin <url>` 이 필요하다고 알린다.

## 6. 사용자에게 보고

한 문단으로: 무엇을 기록했고, 커밋 해시가 무엇이며, 다음 세션은 무엇부터 시작하면 되는지.
